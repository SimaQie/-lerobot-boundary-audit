# 少量新数据重建实验（2026-10-13）

**结论：可以绕开丢失的旧样本重新开发，而且第一阶段已经跑通。** 新下载的数据共 7,684,382 字节，足以覆盖 206 个 episode、25,650 帧及 618 个边界查询。旧材料的价值是问题分类与实现思路；新报告由本次下载的数据和可重跑的实验产生。

## 数据与来源

- 来源：[官方 lerobot/pusht](https://huggingface.co/datasets/lerobot/pusht/tree/7628202a2180972f291ba1bc6723834921e72c19)。
- 固定修订：`7628202a2180972f291ba1bc6723834921e72c19`。
- 格式：LeRobot v3.0；1 个相机、1 个 AV1 MP4、10 FPS、206 个 episode。
- 性质：PushT 模拟环境基准，不是机器人真实采集。适合研究存储、拼接边界与读取关系；不能代表真实传感器同步。
- 数据卡标为 MIT。原卡保留在下载目录；本轮没有转发或重新发布数据。
- 下载包括 README、1 个数据 Parquet、1 个 episode Parquet、info、stats、tasks 和视频。下载前核对文件大小，设置 12 MB 上限，不调用全量 Hub cache。
- 每个文件的大小与 SHA-256 记录在 `samples/source_manifest.json`。

此前计划中的“恢复 fold_towels 旧样本”改为可选历史复核，不再阻塞开发。新数据的正常性、构造缺陷的预期和实际检测结果分别保存。

## 本次重建的实现

独立目录 `lerobot-boundary-audit` 中形成了可安装的 Python 原型。保留旧材料的 MP4 时间表分析思路，重新实现模块与报告，减少对旧目录和训练环境的耦合。

1. 核心 MP4 reader 用标准库解析结构；逐 box 校验长度与父容器边界；真正遍历 `edts/elst`；不认识的复杂结构给出未支持。
2. 通过 run-length 时间表端点计算最坏偏差、按需查询某个 sample，避免展开全视频时间数组。
3. 对 episode 的起止元数据、每个 episode 的首帧/第二帧/尾帧请求做检查；同时核验表格帧序号、时间列、episode 长度和覆盖率。
4. 可选 PyAV 后退 seek 并在有界前向窗口选取最近 PTS，记录实际结果；未安装或未启用解码时明确说明。
5. 输出 JSON 和无服务依赖的 HTML 报告；原始数据只读。

首版没有把原地修改 MP4 的旧脚本直接变成公共修复入口。修复仍需以后验证写入事务、各时长字段一致性、媒体内容不变、可恢复哈希及真实消费者行为。

## 实测结果

测量环境：Windows，Python 3.11，PyAV 16.1.0。结果是这次机器与样本的测量，不是普遍性能保证。

| 实验 | 检查结果 | 含义 |
|---|---|---|
| 原样公开 PushT | PASS，25,650 行检查，618/618 边界查询解码，无发现 | 该修订在本工具的受支持检查范围内正常 |
| 独立顺序解码 | 25,650/25,650 帧，PTS 相对 10 FPS 网格最大偏差 0 | 为 parser 的正常结论提供独立解码对照；不导入项目 parser |
| 第 17 个 episode 元数据整体后移 0.1 秒 | FAIL，只定位到 episode 17，3 个边界请求与实际取帧关系不一致 | 一帧错位能被定位到被修改的 episode |
| 在 episode 17 的首帧前少一个容器 tick | REVIEW，偏差 97.65625 微秒，618 个 PyAV 查询在 100 微秒容差内 | 网格偏差存在，但这次验证没有证明它造成错帧 |
| 每个 sample duration 少一个 tick | FAIL，最大累计偏差 25,649 tick | 检测出全局容器时间轴错误；这不是旧 A1 的单边界缺陷 |

正常样本边界检查在已有环境的一次运行中约 0.30 秒；独立全视频顺序解码约 1.20 秒。另在不继承系统包的干净环境，从生成的 wheel 安装工具、PyArrow 23.0.1 和 PyAV 16.1.0，用隔离模式实际跑通 618/618 查询，首轮约 5.97 秒。均不含安装、下载和全文件哈希时间。该视频只有 96×96，不能外推到高分辨率、多相机大数据。

单 tick 实验从 sample 2335 开始出现偏移。生成器只接受 `moov` 位于 `mdat` 之后的已检查结构，修改时间表和所属容器长度；媒体 payload 字节逐段比较保持一致，哈希保存到实验汇总。

所有缺陷均在人为复制的数据上注入。**本轮没有在原样 PushT 中发现自然故障，没有复现旧版本 torchcodec 的下一帧问题，也没有证明训练质量提高。**

## 接下来的开发重点

小样本足以支撑算法逻辑与错误定位开发，后续验证按功能增加数据，而不是先下载大语料。

1. **实际训练读取器对照。** 在独立环境固定官方 LeRobot、torch 与 torchcodec 版本，检查同样的边界。PyAV 可用不能代替该项认证；单 tick 是否影响取帧要按版本测量。
2. **第二份小型真实机器人样本。** 优先固定一份 SO-101 或 ALOHA 数据的少数 episode/一个必要视频 shard，补真实画面与多相机。事先按实际文件粒度核算大小；v3 一个视频 shard 可能包含很多 episode。
3. **合法复杂时间轴。** 增加 B-frame 的 `ctts` 版本、presentation ordering 与非平凡 edit list 映射；在支持完成前继续明确返回未支持。
4. **报告与支持范围。** 增加最早偏差边界、偏差与读取器后果的并排展示，明确元数据覆盖不足、容器问题和实际读取不一致。
5. **发布前评测。** 固定正常/异常夹具、第三方对照、不同机器安装检查及许可证/贡献归属，然后整理成可引用的软件发布与技术报告。

这次结果已经支持“少量新公开数据能够重建可工作的专项审计原型”。它暂不支持“旧故障普遍存在”或“此功能没有任何开源替代”。公开价值应建立在后续读取器差异、真实用户案例及复现材料上。
