# 0.4.0 local validation protocol

This is a research preview. The 0.3.0 GitHub Actions receipts are historical and do
not certify this new version. No NVIDIA hardware run, PyPI publication, DOI or
natural upstream defect discovery is claimed for this preview.

## Storage prerequisites

The full v3 audit now reads `index`, `episode_index`, `frame_index`, and `timestamp`.
All index columns must be integers with nonnegative, nonnull values. Global index
must equal ordinal position across data shards. This also detects duplicate and
missing indices without retaining a dataset-sized index set. Episode/data shard
references are checked where rows are present. Ordinary audit remains a full
storage check, not an episode-subset certification; use complete metadata/data
and select episodes for consumer probes instead.

Missing fields and broken prerequisites produce JSON/HTML, without reporting
unperformed checks as passed. Corrupt data shards can be reported alongside
independently found errors in other shards. Prerequisite-invalid inputs and
index/shard defects block repair; no source row is repaired or silently reordered.

## Original control suite

The packaged 0.4 fixture derives from the original official 0.3 recordings and
merge (LeRobot 0.6.1, PyAV 15.1.0). Seven additional controls are produced by the
auditor environment; its encoder version is separately recorded in suite.json.
The original pre-encoding camera/episode/frame oracle remains unchanged.

Six passing controls: recorded-a, recorded-b, official merged output, guarded
repaired offset, multiple data shards, and re-encoded video without B-frames.
Seven intentional defects: offset, camera payload swap, global-index shift,
duplicate global index, wrong action, repeated pixel frame, exchanged pixel order.
These are 13 fixtures and seven controlled fault types, not a real failure corpus.

Full protocol: PyAV/TorchCodec × eight phases × 13 cases = 208 combinations.
The `long-window` phase uses sparse offsets −8/−4/−1/0/+1/+4/+8.
`random` uses fixed seed 20261014 and repeats reads after random access.
`persistent` reuses two spawned workers across two epochs. Normal `window` uses
−1/0/+1; `batch` uses four rows; `subset` selects odd original episode indices.
Pixel-fault controls require decoded wrong identities. Index/action controls
require explicit row/action/padding evidence. Runtime exceptions alone cannot
meet either requirement. Any errors are retained in per-check JSON, including
errors caused by duplicate index mapping; they are never substituted for evidence.

```sh
lerobot-boundary-audit demo --out demo-v040
lerobot-boundary-audit conformance demo-v040 --python PATH_TO_OFFICIAL_PYTHON --jobs 2 --out results-v040
```

To generate new official recordings plus derived controls, install `.[fixtures]`
in the auditor environment, and use `fixture-suite` with the separate official
interpreter. Normal audit/demo users do not need NumPy or Torch in their environment.
Fractional FPS has parser-level regression tests; the full official fixture
matrix is H.264 at 30 FPS. Other codecs and fractional-FPS training are not covered.

## Ordinary footage probe

The core builds bounded requested row/window references using complete audited
metadata, and recorded actions from the actual data tables. A separate consumer
copies metadata/data and selected camera streams into a bounded temporary view.
Its projected `info.features` names the selected cameras; other source camera
features do not enter the loader. The temporary copy is discarded after the run.
The source hashes are checked before and after the entire operation.

Reference RGB arrays are produced by sequential presentation-order PyAV decode,
without using the tested loader's seek function or deriving frame identity from
the query timestamp. The expected ordinal positions still assume complete ordered
episode ranges, as validated by the storage preflight. This is a runtime-reading
comparison, not an independent recording-time oracle.

Exact unique matches are reported as exact. Approximate cross-backend matches use
uint8 MAE <=2 and at least 0.25 separation from adjacent candidates. These numerical
rules are heuristics, not semantic identity guarantees or calibrated confidence.
Exact duplicate neighbours and uncertain matches are `ambiguous`, giving PARTIAL
rather than PASS. Neighbour candidates do not identify arbitrarily distant frames.
Resizing/cropping/depth conversion and arbitrary custom training transforms are
not supported by this probe. PyAV matches share PyAV RGB conversion with the
reference; all paths share FFmpeg ancestry.

Ordinary camera swaps or frame duplication already present in the source can be
consistent with sequential source decode. Detecting those recording-time defects
needs source lineage or known identities; use the authored-marker suite for that
guarantee. The tool does not infer physical camera/action synchronization.

```sh
lerobot-boundary-audit probe-loader samples/agibot2026 --camera observation.images.hand_left --camera observation.images.hand_right --python PATH_TO_OFFICIAL_PYTHON --phase workers --max-rows 6 --out results-real-probe
```

Limits: query rows, radius, sequential decode frames, reference image bytes,
temporary view bytes, and per-process elapsed timeout are configurable. The
reference-array budget excludes decoder, Torch and worker memory. The core still
scans complete tables and hashes complete source files; sampling is a consumer
coverage budget, not a claim of sublinear total preprocessing.

## Descriptive same-input comparison

Use separate installation environments. Frozen competitor sources:

- lerobot-doctor: `38681941b6866c6d97d49502ab991c21dfbb9d9b`
- openbot-data: `cd7720d55503a58fbbabc1b3d3ce48d9279518d7`

Install those source checkouts, including OpenBot's `lerobot` extra. This compares
the pinned source builds, not necessarily their PyPI release contents. Package and
media dependency versions are recorded with each run. No competitor source is patched.

```sh
python research/compare_v040.py --suite demo-v040 --python PATH_TO_COMPARISON_PYTHON --loader-results results-v040 --out comparison-v040
```

Doctor configuration: metadata, temporal, videos; warnings remain visible.
OpenBot: local LeRobot, full media integrity, error threshold. Own storage:
decode enabled, 0.3 baseline audit code from commit 29ac3ba versus 0.4. Full loader:
the measured PyAV window report. All inputs are identical and protected by hashes.
Original input bytes and raw per-tool JSON are retained, together with process
output and elapsed time. Output redacts the local dataset root.

OpenBot currently reports singleton scalar-storage shape errors on the clean
official fixture. Overall error status therefore cannot demonstrate injected-fault
detection; inspect additional finding codes versus the clean merged control.
Here "clean" means satisfying this suite's row/pixel/action-value expectations.
The official producer stores the one-dimensional numeric features as scalars;
our action checks compare values after flattening and do not certify tensor rank
for a policy. OpenBot's stricter shape finding is not proven to be a false positive
merely because the official loader accepts the fixture.
Doctor warns on shifted and repeated global indices. Warnings are detections at
the warning level, not misses merely because its default exit policy accepts them.

No universal score or detection-rate ranking is computed. The tools have different
scope and severity semantics. Source-pinned builds use different media runtimes,
and elapsed time includes interpreter startup. No peak-memory or bytes-read ranking
has been measured here. A camera swap that passes metadata checks but fails known
pixel identity demonstrates a coverage distinction, not that another tool is broken.

Local measured results are saved in `research/runs/v040/`; a compact validated
receipt will be retained in `research/results/v040/` after all checks complete.
